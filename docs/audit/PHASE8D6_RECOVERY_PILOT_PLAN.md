## 1. Objective

**Why run_002 is needed:**

Phase 8D run_001 exhausted its entire 74-attempt HTTP budget with **zero successful
movie retrievals**. Every request failed with `[WinError 10054] An existing connection
was forcibly closed by the remote host`, indicating a network-level obstruction on
the broadband ISP path.

After switching the router's upstream WAN to a 4G cellular connection:
- Phase 8D.3 TLS probes confirmed connectivity (TLS 1.3 handshake successful)
- Phase 8D.5 authenticated smoke test returned HTTP 200 with valid JSON from
  `GET /3/configuration`

Run_002 will retry the same 40-movie pilot over the working 4G WAN route.

## 6. Circuit Breaker Protection

| Parameter | Value |
|---|---|
| Failure threshold | 5 consecutive failures |
| Transport error patterns | 12 recognized patterns |
| Test coverage | 28 unit tests |
| Behavior on trip | Stops all subsequent requests immediately |

The circuit breaker (`TMDBClient`) monitors consecutive transport-level failures.
After 5 consecutive failures (e.g., connection reset, timeout), it trips and prevents
further HTTP attempts, preserving budget for the remaining movies.

**Run_002 benefit:** On the working 4G network, the circuit breaker should not trip
unless TMDB itself experiences an outage. In run_001, it tripped after 5 movies
(consuming ~20 of 74 budget on retries before detection).

---

## 7. Stop Conditions

The pilot stops when **any** of these conditions is met:

1. **Budget exhausted** — `cumulative_requests >= 74`
2. **Circuit breaker tripped** — 5 consecutive transport failures
3. **All movies processed** — 37 movies with TMDB IDs queried (success or failure)
4. **Authorization revoked** — env variable changed during execution (checked at startup)
5. **Unrecoverable error** — Python exception or OS-level failure
